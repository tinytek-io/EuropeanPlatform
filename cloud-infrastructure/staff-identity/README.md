# Staff identity

One file per environment (`<environment>.yaml`, named after the Terraform environment) decides who may
sign in to the back-office and which tools may sign staff in through the back-office's OIDC provider.
It is the only place staff are managed: there is no admin UI, and nobody has a password — staff sign
in with a one-time code emailed to the address listed here.

```yaml
staff:
  - id: jane.doe            # the OIDC subject other tools key accounts on; never reuse it
    email: jane.doe@example.com
    name: Jane Doe
    groups: [staff, admins] # everyone is in `staff`; `admins` also unlocks admin actions
    active: true            # offboard by setting false and deploying; keep the entry
clients:
  - clientId: forgejo
    displayName: Forgejo
    redirectUris: [https://git.example.com/user/oauth2/back-office/callback]
    postLogoutRedirectUris: []
    allowedGroups: [staff]  # who may sign in to this tool
```

Changes take effect on the next deploy: the file ships with the back-office, which validates it at
startup and refuses to start on a typo, an unknown key or group, or a duplicate id or email.
Offboarding ends the person's sessions on their next request. Client secrets are generated by
Terraform per `clientId`; they never live in this file.

The open-source project ships every list empty. Your fork commits its own entries.
